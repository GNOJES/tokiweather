# 토끼날씨 갱신 신뢰성 개선 설계

## 목표

두 종류의 위젯을 함께 써도 자동 갱신이 유지되고, 날씨 조회 실패가 성공이나 0°C로 표시되지 않게 한다. 인증키가 진단 로그에 남지 않게 하며 공개 배포 전 키 운영 방식을 명시한다.

## 현재 동작과 변경 기준

1. 두 위젯 리시버가 같은 `toki_weather_periodic_update` 작업을 예약하고 취소한다. 한 종류를 제거해도 다른 종류가 남으면 작업을 유지한다. 위젯 추가 시 저장된 15/30/60분 설정을 사용한다. 사용자 지정 주기는 설정에서 저장했을 때만 변경한다.
2. `WeatherRepository.fetchAndSave()`는 `Result<CachedWeather>`를 반환하지만 날씨 탭과 설정 화면은 결과를 검사하지 않는다. 실패 시 성공 토스트를 띄우지 않고, 설정 저장 후 새로고침만 실패한 경우 설정 저장 사실과 날씨 갱신 실패를 분리해 안내한다. 취소된 코루틴은 일반 오류로 바꾸지 않는다.
3. 기상청 API의 HTTP 성공만으로 유효한 날씨 데이터라고 간주하지 않는다. 응답 결과 코드가 정상이고 현재 기온 필수 항목을 파싱할 수 있을 때만 새 데이터를 캐시에 저장한다. 예보 항목이 누락되면 임의의 0°C를 표시하지 않는다. 실패 시 마지막 정상 캐시는 보존한다. 대기질 실패는 기존처럼 날씨 전체 실패로 취급하지 않되, 관측값과 관측시각은 별도로 다룬다.
4. Debug 기상청 HTTP 본문 로그는 인증키가 포함된 요청 URL을 기록한다. 요청/응답 URL과 본문을 로깅하지 않도록 바꾸고 오류 로그에도 원본 URL을 기록하지 않는다. `BuildConfig`에 포함된 클라이언트 키는 APK에서 추출될 수 있으므로 숨겨진 비밀로 취급하지 않는다. 공개 배포 시 공공데이터포털 트래픽 한도와 키 교체 절차를 점검한다. 서버 프록시는 사용량 남용이 실제 문제가 될 때 별도 설계한다.

## 범위와 완료 조건

- 하단 탭 아이콘, 위젯 디자인, 현재 3일 예보 범위는 유지한다.
- 위젯 두 종류를 함께 추가하고 하나를 제거해도 나머지의 예약 작업이 살아 있다.
- 네트워크/기상청 응답 실패는 성공 메시지와 새 캐시 쓰기를 발생시키지 않는다.
- 결측 현재 기온이나 예보 최저·최고가 정상 수치 `0`으로 위장되지 않는다.
- Debug 실기기 로그에 두 서비스 인증키가 등장하지 않는다.
- `./gradlew testDebugUnitTest assembleDebug` 성공, 연결된 실기기에서 예약·수동 새로고침을 확인한다.
